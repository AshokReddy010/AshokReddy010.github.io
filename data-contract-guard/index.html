Data Contract Guard

A Python tool and GitHub Action that enforces data contracts written in YAML: it validates CSV, Parquet and JSON files against column, key, range and business-rule promises, drafts a contract from sample data, and classifies contract changes as breaking or safe with the version bump each needs. A browser playground runs the real package with Pyodide.

The broken example has ten planted problems: a duplicated order number, a malformed id, a blank customer, a quantity of "two", a negative quantity, an unknown status, an order that ships before it was placed, a 90% discount, an impossible date and a bad email (a warning only).

The same checks run from the command line (contract-guard validate -c orders.yml orders.csv) and as a GitHub Action that writes this report to the pull request's job summary and fails the build on errors.

Case notes

Upstream teams change data without warning: an enum gains a value, a column is renamed, negative quantities slip in. A contract makes the boundary between teams explicit and testable.

Approach

  • CSV is read as text so a value like 12a in an integer column is caught, not silently converted.
  • A broken contract never passes data: every contract mistake is reported before any row is read.
  • Breaking is defined from the consumer's side, and diff enforces the semantic-version bump.
  • The action writes a Markdown report to the pull request's job summary and can emit JUnit XML.
